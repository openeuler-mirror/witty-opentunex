# 瓶颈分析域强制约束

constraints_version: "v1.0"

## B-01: 重新执行
每次触发都必须重新从头执行完整分析流程，不得引用历史数据或之前的回答。

## B-02: 数据目录约定
- 写入路径：${WORK_DIR}/analysis/[skill_name]_collect/
- 读取路径：${WORK_DIR}/analysis/[skill_name]_collect/
- 禁止直接写入 ${WORK_DIR}/analysis/ 根目录
- 所有路径中的 ${WORK_DIR}/ 均指用户指定的工作目录，可通过 OPENTUNEX_WORK_DIR 环境变量自定义
- 远端场景（目标为远端服务器）时，`${WORK_DIR}` 为远端路径：上述读写均须经 `opentunex-remote-execution` 的 ssh 机制在远端执行（读用远端 cat/grep 流回上下文、写用本地 Write 后 scp 上传到远端路径），禁止在 agent 本地操作 `${WORK_DIR}`。详见 `opentunex-remote-execution/references/work_dir_remote_semantics.md`

## B-03: 禁止自行采集
子技能禁止自行采集数据，必须基于已采集的数据进行分析。

## B-04: 数据缺失处理
数据缺失时由协调器调用数据采集 Skill，子技能不自行采集。

## B-05: 通用分析与场景化分析必须并行
两者视角互补，不可串行替代。输出契约中必须包含并行启动的时间戳证据。

## B-06: 场景化分析全量调度
不做选择性过滤，由各场景自行判断适用性。

## B-07: 结果融合必选
两类分析结果必须经过融合，确保调优层收到一致、无冲突的结论。

## B-08: 子技能执行模式选择

按以下优先级选择子技能的执行模式：

### 模式 1：子智能体模式（默认）
子智能体工具可用且能力充足时，应通过子智能体工具启动独立上下文执行：
1. 上下文隔离：子技能在独立上下文执行，避免主上下文膨胀
2. 并行能力：子智能体可并行执行，内联只能串行
3. 可追踪性：子智能体有独立的输出契约
4. 职责边界：主智能体只负责调度和融合

### 模式 2：内联执行模式（降级路径）
**满足以下任一条件时，必须降级为内联执行**（在当前上下文串行读取各子技能 SKILL.md 依次执行）：
- 子智能体工具不可用（如 harness 未启用 Agent 工具、未配置可用的 subagent_type）
- 子智能体工具能力不足（如无法写文件、无法执行远端脚本、权限受限）
- 用户明确要求内联执行

降级执行时必须在输出契约中标注 `execution_mode: "degraded"` 并说明降级原因；不得在不标注的情况下静默内联执行。

### 模式选择规则
- 模式 1 与模式 2 是按条件互动的二选一，**不是优先级冲突**。
- 子智能体工具可用且能力充足时，不得以"更高效/更方便"等主观判断绕过子智能体模式。
- "数据已加载到上下文"不是跳过子智能体的正当理由。子智能体独立加载自己的上下文，应将数据路径（而非内容）写入输入契约。
- 路径不匹配不是豁免条款。数据目录路径（`${WORK_DIR}/` 或用户自定义路径）只是输入契约中 `data_dir` 字段的值，路径差异不影响执行步骤选择。
- 当降级条件命中时，**必须主动落地降级路径**，不得因 B-08 的禁止性措辞而拒绝内联执行。

## 确认方式
子智能体必须在输出契约的 constraints_acknowledged 字段中列出已遵守的约束编号，并在 constraints_version 字段中填写本约束文件版本号。
示例：constraints_acknowledged: ["B-01: 重新执行", "B-02: 数据目录约定", "B-03: 禁止自行采集", "B-04: 数据缺失处理", "B-05: 通用分析与场景化分析必须并行", "B-06: 场景化分析全量调度", "B-07: 结果融合必选", "B-08: 子技能执行模式选择"]
